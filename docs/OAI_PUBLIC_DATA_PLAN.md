# 公开 OAI 实验数据接入方案

制定日期：2026-09-21。第一版已按本文方案接入一组 QUEST 公开 OAI 记录，完成来源追踪、查询、完整记录统计、核心网路径视觉回放和按终端 CSV 导出；实时 OAI/USRP 接入仍属于后续阶段。

第二步联动版已在原“核心网实验”中加入 OAI 输入来源：网关按数据集 ID 和全局记录序号重新核验 SINR，页面要求用户填写数据源未提供的实验信号功率。单次注册和网页压测调用正式 AMF→SMF→UPF 链路，因此停止网元会形成真实的超时、重试或失败结果；启动后可重新实验。网元启停依赖 `controller` 能访问 Docker Compose，部署环境未提供控制器时只保留数据浏览和故障结果显示。

## 1. 目标与第一版成果

让 LiteCore 网页实验台能够读取一组有来源的公开 OAI 实验记录，按终端查看测量曲线、浏览原始记录、播放历史变化并导出选定范围的数据。

第一版演示：打开「OAI 实验数据」→ 选择一组 QUEST 实验 → 查看来源与采集条件 → 选择终端 → 查看 SINR 等已核实指标 → 播放/暂停、定位记录 → 导出结果。

这项工作回答的是“平台能否读取并分析外部 OAI 实验数据”。第一版是离线数据接入，不代表平台已与正在运行的 OAI 联通。AMF/SMF/UPF 的教学注册流程继续保留，OAI 历史记录直接进入观测页面，不触发模拟注册、会话创建或 UPF 包计数。

## 2. 数据源选择

| 优先级 | 来源 | 已核实内容 | 用途与限制 |
| --- | --- | --- | --- |
| 首选 | [TUM-LKN QUEST](https://github.com/tum-lkn/QUEST) | 仓库有 2/3 UE 实验 CSV、调度性能及 IRTT 时延记录；README 提及 SINR、MCS、PRB 等字段 | 首版只接一个双终端运行文件。字段、单位与物理采集条件仍需核对代码/论文 |
| 后续 | [DETERMINISTIC6G OAI 时延测量](https://zenodo.org/records/10829232) | `OAI5G.zip` 约 217 MB，CC BY 4.0，说明为 OAI 平台时延测量 | 扩展时延分析；不作为缺失信号功率的替代来源 |
| 备选 | [OAI RAN KPM 数据集](https://zenodo.org/records/17935683) | KPM 指标含吞吐、时延、PRB；说明明确使用 RFSim；CC BY 4.0 | 若首选数据的解释资料不足，可先接运行指标；必须标注 RFSim 仿真环境 |

QUEST 的首个候选文件为：

[`datasets/users_2/run_1/scheduler_QUEST/gNB_results.csv`](https://github.com/tum-lkn/QUEST/blob/main/datasets/users_2/run_1/scheduler_QUEST/gNB_results.csv)

此前读取的样例没有表头，每行有 10 个值；README 中列出的字段不足以完整解释这 10 列。**不能直接按 README 的列表逐列命名。** 需要找到生成 CSV 的代码或数据处理脚本，核实每个位置。首版只加载一组数据，不下载所有调度器和所有重复运行。

QUEST 仓库显示 Apache-2.0 许可；下载时还需核实该许可是否覆盖选取的数据文件、是否另有数据使用声明，保存许可证与引用信息。引用研究论文并保留作者信息。

## 3. 当前已有能力与缺口

| 模块 | 当前状态 | 本轮要补的能力 |
| --- | --- | --- |
| `ue/trace.go` | 校验有表头的约定格式 CSV，识别测量值、记录来源和 SHA-256 | 保留为命令行信道实验工具；QUEST 原始文件无法直接输入 |
| `ue/benchmark.go` | 使用兼容的信号功率/SINR 逐行创建独立实验 UE | 不是此次 OAI 观测接入的主路径 |
| `gateway/` | HTTP 接口读取 LiteCore 网元状态 | 增加独立的 OAI 数据集查询接口 |
| `frontend-live/` | 显示 LiteCore 实时响应，后端不可达时使用演示数据 | 增加独立 OAI 数据页面和历史回放状态 |

原有 `ue/` 是可执行程序包，不能直接作为 Go 库导入网关。新数据适配器放在网关模块内的独立包；采用现有校验、来源追踪的做法，避免跨 `main` 包引用或把 OAI 的不同指标硬塞进现有 Register 请求。

## 4. 数据流与模块安排

```mermaid
flowchart LR
    A[公开数据源：固定版本] --> B[原始文件归档与校验和]
    B --> C[QUEST 专用适配器]
    C --> D[标准记录、来源清单、质量报告]
    D --> E[网关只读查询 API]
    E --> F[OAI 实验数据页面]
    F --> G[历史回放、图表、筛选与导出]
```

建议新增以下文件和目录，名称在实施时可按仓库习惯调整：

| 位置 | 职责 |
| --- | --- |
| `gateway/oaidata/` | 数据记录类型、QUEST 解析、校验、文件查询及指标统计 |
| `gateway/cmd/oai-import/` | 离线导入命令，生成标准数据包和质量报告 |
| `gateway/oai_handlers.go` | 数据目录、详情、记录、图表和导出 HTTP 接口 |
| `frontend-live/src/oai/` | 数据集选择、终端筛选、图表、记录表和回放控制 |
| `datasets/oai/raw/` | 原始文件，保存后不修改；大文件不提交 Git |
| `datasets/oai/processed/` | 标准化数据包，可由导入命令重新生成 |
| `docs/OAI_DATA_SOURCES.md` | 经核实的版本、许可、采集条件、字段表及解释证据 |

首版使用文件存储，不引入数据库。数据包包含 `manifest.json`、`records.jsonl`、`quality-report.json`。导入完成且校验通过后再发布整个数据包，失败文件不能出现在可用数据集列表里。网关重启后重新扫描已发布数据；容器部署时将数据目录只读挂载给网关。

下载由专用命令从明确来源执行；网关 API 只接受已登记的数据集 ID，不接受任意 URL 或服务器文件路径。第一版页面选择预导入的数据集，暂不做任意文件上传。

## 5. 数据口径

### 来源清单

每个数据集保存：数据集 ID、来源 URL、仓库 commit 或 DOI、原文件相对路径、原文件 SHA-256、下载时间、许可/引用、运行编号、调度器、采集环境、适配器版本、字段映射和时间解释依据。

采集环境分别记录为“RFSim 仿真”“USRP 空口”“线缆实验”或“待核实”。只有对应原文证据确认后，才在页面写“空口实测”。公开数据和本实验室数据分别标明。

### 记录内容

每条记录至少保留：`dataset_id`、原文件标识与 `source_line`、稳定的记录序号、原始 UE 标识、原始 frame/slot，以及已核实的测量字段。标准时间可为空，未提供或无法解释的指标为 `null`。

- UE RNTI 按字符串保留；终端标识作用域限定在一组实验内，不把不同运行的相同 RNTI 合并为同一设备，也不把它称为 IMSI。
- SINR、MCS、PRB、时延的列位置、缩放和单位逐项核实后启用；未知列保留原值，不随意命名。
- 没有 RSRP、信号功率、注册事件或包计数，就显示“数据未提供”；不能补零、用随机数补齐或从有调度记录推断“注册成功率”。
- 调度延迟、业务 RTT、LiteCore 注册 RPC 延迟分别标注。没有明确定义和统计窗口时，不把 TBS 等字段直接解释为吞吐量。
- 缺失、非有限数值、异常列数、重复行、时间异常写入质量报告。相同帧/时隙可能有多个合法记录，不能按时间戳直接去重。

### 时间轴与回放

先从生成代码及实验配置确认帧号含义、numerology 和 slot 编号语义，再恢复时间轴。若确认为标准 NR 的帧内 slot 计数，才按 10 ms 帧长及对应 slot 时长计算；对 SFN 回绕、进程重启、漏记及顺序问题分别处理。

若时间依据不足，首版仍可按“原始记录序号”查看和播放，页面标注“按记录播放”，不伪造毫秒轴。此时禁止生成每秒速率类指标。

确认时间后开放按采集时间回放。回放速度只影响屏幕推进速度，不改变数据中的时间、测量值及统计结果。导入日期不作为实验采集日期。

## 6. 查询接口与页面行为

拟新增 API：

| 接口 | 返回内容 |
| --- | --- |
| `GET /api/oai/datasets` | 可用数据集、来源类型、记录数、可用指标及时间轴状态 |
| `GET /api/oai/datasets/{id}` | 来源、字段说明、质量报告摘要及实验配置 |
| `GET /api/oai/datasets/{id}/records` | 按终端/时间或记录区间筛选，使用游标分页，单次最多 1000 条 |
| `GET /api/oai/datasets/{id}/series` | 指定指标的显示序列，限制点数并返回降采样说明 |
| `GET /api/oai/datasets/{id}/export` | 导出筛选范围内的完整标准记录和来源字段 |

接口由 `gateway/oaidata` 提供数据，不调用 AMF/SMF/UPF；即使这三个教学网元没有启动，OAI 数据查询仍应可用。

网页增加独立「OAI 实验数据」入口，首版包含：

1. 数据集选择与来源说明，包括原始链接、采集环境、运行编号。
2. 终端筛选、已核实的 SINR 曲线及其他可用指标。
3. 播放、暂停、进度定位；有时间依据时支持 0.5×、1×、2× 倍速，无依据时按记录播放。
4. 原始记录表，可追溯到源文件与行号；原始缺失值显示为“未提供”。
5. 选定范围的统计与 CSV 导出。CSV 文本字段按电子表格安全要求转义，原始文件保持不变。

该页面拥有独立于现有 live/demo 的数据状态。查询失败时显示错误并允许重试，不自动展示随机演示值。离开页面或切换数据集时停止旧回放并取消旧请求，防止记录混入新实验。

原始数据用于统计和导出，图表降采样仅影响绘制；选取一个指标后展示清楚单位、测量方向与统计对象。若存在缺口或实验分段，曲线不跨段直接连线。

## 7. 实施步骤与预计工作量

估算以 1 名开发者、现有环境可用、首选数据解释资料足够为前提；时间轴或许可证据缺失会延长资料核实阶段。

| 阶段 | 工作内容 | 交付与通过条件 | 预计 |
| --- | --- | --- | --- |
| A 数据核实 | 固定 QUEST commit，取一个文件及相关代码，核实许可、10 列定义和时间依据 | 来源清单、字段对照表、原始样本。至少终端标识及一个指标有完整解释；不确定项明确标记 | 1–2 天 |
| B 离线导入 | 写 QUEST 专用适配器、标准数据包、质量报告，处理缺失/异常/时间分段 | 一条命令可重复生成相同逻辑记录，源文件不变，逐行可追踪 | 1–2 天 |
| C 网关查询 | 加载文件、分页、终端筛选、序列查询及导出 | 网元关闭时仍可读取；接口结果与标准记录一致 | 1 天 |
| D 页面回放 | 独立入口、来源提示、曲线、记录表和播放控制 | 可完成一组双终端数据的浏览与回放，错误时不混入演示数据 | 2–3 天 |
| E 验收与材料 | 样本对照、导出核验、边界检查，记录演示操作 | 验收记录、来源说明、使用文档与演示截图 | 1 天 |

第一版总计约 **6–9 个工作日**。阶段 A 的结论决定 B 的字段映射：时间不足以解释时先做记录序号回放；若连一个核心指标都无法可靠解释，就改选备选数据集，并将交付指标相应调整为吞吐/资源使用等已核实字段。

## 8. 验收标准

- 来源可追溯：固定版本、许可、原文件 SHA-256、字段定义证据完整。
- 样本对得上：抽取前/中/后及异常边界合计至少 20 条记录，对照原始值、终端、单位和显示值，允许的数值误差须有明确理由。
- 数量对得上：输入数据行数 = 接收记录数 + 明确拒绝的行数；不悄悄丢行，重复和缺失情况有报告。
- 时间可解释：核实模式下验证时间换算及可判定的回绕/重启；无法确定时使用记录序号且不会计算伪造的每秒速率。
- 统计可复现：筛选范围、有效样本数和单位一致，显示用降采样不改变统计及导出原始记录。
- 页面可操作：播放/暂停/定位有效，换终端或数据集不混数据，不同播放速度下最终统计一致。
- 故障可识别：后端不可用、空数据、不存在的数据集、未知指标都明确展示错误或空态；不回退成伪装的 OAI 数据。
- 数据可持久：重启网关后仍能选择同一份已导入数据；原文件校验和不变。
- 原有功能可用：LiteCore 注册、注销、压测和演示模式无回归。

第一版已对适配器样例和异常行、网关筛选/降采样及导出做针对性测试，并通过 Go 测试、静态检查、前端生产构建和浏览器回放验收。尚未接入实时 OAI、USRP 空口或本实验室采集端。

## 9. 第一版之后

第一版完成后，接入第二组运行或另一种调度器，增加同口径对比。之后再编写实时采集适配器读取实验室 OAI 的日志/指标接口，复用已经确定的标准记录和图表接口。实时接入单独处理时间同步、采集中断和在线状态，不从历史记录推断实时在线。

向老师汇报第一版时可以说：

> 平台已接入公开 OAI 实验记录，支持来源追踪、按终端查看已核实指标、历史回放和导出。当前使用公开离线数据，后续将同一套分析界面连接实验室 OAI 采集端。

该表述只在实施及验收完成后使用；“USRP 空口实测”等采集属性以数据源证据为准。
